# E-PRODUCT research decision 2026-07-11

## Purpose

Dispose of the bounded product-journey candidates without promoting a local
model, durable record, or guarded diagnostic into a player feature.

## Disposition

`reject` adoption of the combined candidate now. The first-player, menu, chat,
claim, adventure, wake, and transfer portions are also `blocked_external` for
client/protocol proof because F-SAFETY deliberately withdrew Java daemon
adapters. This is a non-adoption decision, not a request to restore them.

## Evidence and invariant assessment

The [hypothesis](../experiments/e-product-20260711.md) and
[run](../runs/e-product-20260711.md) record reproducible baseline and candidate
local models. CLI help, local authenticated web smoke, locale parity, Java
containment, adventure-catalog validation, and purchase preflight passed.
PostgreSQL tests passed the durable wake, temporary session, delivery migration,
replay, and exchange models. The exact guarded Java menu, claim, and playable
attempts all returned `BLOCKED` as required.

No invariant was traded away: no adapter, command, route, controller, product
source, owner document, or state row changed. The curation comparison has zero
implementation cost only because it is not implemented; it therefore cannot
show player value or maintenance benefit.

## Reconsideration

A future adoption task needs trusted identity and session attestation, an owner
contract, a real bounded Java or protocol client, consented test accounts, and
client-observed success, failure, recovery, locale, and accessibility evidence.
It must compare a registered curated route with the broad bundle and measure
completion, error recovery, maintenance, and proof cost. A progression decision
also needs a combined economic workload with explicit exploit assertions.

Retain `/tmp/lkjmc-e-product-0zl9b7n9` and
`/tmp/lkjmc-e-product-f_ho4imp` through review, then remove only those owned
roots. No adoption task is created by this decision.
