# E-OBS decision 2026-07-11

## Purpose

Record the evidence-based research disposition without changing shipped behavior.

## Disposition

decision registers no command, metric, operation history, bundle, or adapter.

## Evidence

The base is `d20e5e532db9d3a5577f567dd6a5a24fdc51eea1`; hypothesis commit is
`53dd2e4218de57dcf531b02707d2071c6de8bce4`; harness commit is

All three variants crossed real daemon HTTP, PostgreSQL, local-process, and
existing audit boundaries. The harness now preserves distinct client request,

from a response. No independently emitted observer event is available on this
boundary, so `correlation-end-to-end` is `BLOCKED`/unsupported; matching
synthetic records are not a pass. Bounded metrics used four fixed series; the
bundle added actual audit, status, and log reads. The run's replayed raw index
is linked in the run.

## Comparison

Events measured +5.301 ms median workflow overhead and 8,221 bytes. Adding
metrics measured +4.518 ms and 8,532 bytes with four series. The
history/bundle variant measured +1.814 ms and 22,573 bytes. p95 uses the
nearest-rank fifth sample for five repetitions. The sample cannot rank these
small overhead estimates, but bundle retention is materially larger. In-process
lookup was 0.001, 0.005, and 2.033 ms respectively; it is not a human
diagnosis-time result.

The canary positive control was detected and removed; a final scan of every
retained file, including the index, checksum, and scan record, was clean. Auth
denial returned HTTP 403, timeout continuation had a later successful list, and
an immediate child failure returned `instance.error`. The old matching
response/event-ID result is withdrawn: those event IDs were response-derived.
The corrected harness keeps client request, daemon response, and observer event
IDs distinct; its self-test rejects mismatched and absent IDs, empty records,
and blank client, daemon, or observer IDs. Current history
has no request identifier and this boundary has no independently emitted observer
event provenance, so `correlation-end-to-end` is `BLOCKED`/unsupported. The
database-delay query did not delay a daemon handler, and the Velocity-shaped
disconnect was truthfully denied because the Java adapter is withdrawn. Those
gaps block a complete fault claim.

## Required combination work

Before a selection, combine `CP-OPS-JOURNAL` and `DW-RUNTIME-FLOW` with the
candidate event schema on a real lifecycle command. The durable record must
carry an operation/request correlation identifier through effects and
observations. Re-run the same fault matrix with a bounded daemon-path database
delay and with any future attested JVM adapter; do not replace either with a
fake command or plugin response. Then compare a minimal metric implementation
with a deliberately introduced standard telemetry-library prototype.

## Reconsideration and boundary

Reconsider only with at least thirty repetitions, a real handler-delay fault,
an independently emitted observer event with attested provenance, durable
correlation, a full redacted bundle, and a safe adapter-specific plugin-disconnect
proof. Preserve `cc5ad5c6380a20d4232c1b142e0002c3b0da192a` and the run evidence
for that branch. E-SYNTHESIS owns any later selection and an adoption task would
own owner-contract and state changes.

No owner or state documentation changes are appropriate: this is research
only. The decision probe is satisfied by this committed decision; correlation
and fault-diagnosis remain blocked facts, not passing product claims.
