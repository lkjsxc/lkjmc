# E-MENU research decision

## Purpose

Interpret bounded local-menu and daemon-candidate observations without changing
an adapter, route, Java command, controller record, owner contract, or state
claim.

## Disposition

`retain boundary; no adoption.` The local documentation surface remains its
existing bounded capability. Daemon-produced view-model candidates and
renderer-derived compiled-resource specimens are not adopted as a Java menu.
Java and protocol-player evidence remains `BLOCKED` under F-SAFETY.

## Evidence and costs

The [hypothesis](../experiments/e-menu-20260712.md) and
[run](../runs/e-menu-20260712.md) record passing catalog, locale, document-core,
Paper local-surface, manifest-selected compiled-bundle, malformed-loader,
daemon-shape, and no-database outage observations. The explicit source manifest
excludes the run and decision inputs; replay verifies selected-source provenance
rather than a self-changing full resource. The layout specimen is useful for
source-slot review only: it has zero Bukkit interaction, client rendering,
accessibility, consent, or player-session evidence.

The daemon candidate test produced and checked 17 PostgreSQL-backed response
shapes. It establishes neither a trustworthy Java caller nor a route, cache,
failure display, mutation fence, or player-visible action. The no-database
response only establishes a daemon error at a Unix-socket boundary. It does not
show a local menu outage behavior.

Both guarded protocol-player attempts returned `BLOCKED`, as required. Their
cost is deliberately not bypassed by a mock endpoint, fake inventory, fake
player, placeholder row, or daemon client.

## Reconsideration

A separate adoption task requires trusted Java identity/session attestation, an
owner contract, bounded real adapter work, and an approved disposable platform
harness. It must observe a real client inventory route, malformed/local-missing
content, daemon outage and recovery, locale selection, accessibility, and
protocol player behavior. It must also demonstrate that scheduler callbacks do
not block on database, filesystem, network, or process work.

Until then, retain the runner and `/tmp/lkjmc-e-menu-final-20260712-tip` for review. The
next executable step is an independent replay followed by a separate review of
the F-SAFETY containment boundary; it must not create an adoption/controller
task.
