# E-SYNTHESIS decision 2026-07-12

## Purpose

Synthesize the recorded experiments without merging their harnesses, changing
product behavior, or claiming a controller transition, external service, or
live result.

## Disposition

**No product mechanism is adopted.** The selected set is limited to inputs for
separately approved owner proposals: `S-CONTRACT` (neutral source, domain
shards, checked adapters), `S-SECURITY` (fail-closed revision repair shape),
`S-QUALITY` (deterministic falsification techniques), `S-CUTOVER` (private
schema rehearsal), and `S-LOCAL-MENU` (the existing local-only boundary).
They are not code selections and authorize no merge, command, adapter, schema,
or state-matrix row. The complete per-ID disposition is in the
[E-SYNTHESIS inventory](e-synthesis-dispositions-20260712.md). Its 34 former
gaps now have bounded safe or guarded evidence attempts; none is adoption.

## Hard gates

- A post-launch effect with no durable completion remains ambiguous. It blocks
  `CP-EXEC-*`, `CP-OPS-JOURNAL`, actor, lease, broker, and executor adoption.
- No independently emitted, attested observer event crosses the daemon path.
  It blocks `CP-OPS-JOURNAL`, `DW-RUNTIME-FLOW`, and observability adoption.
- F-SAFETY remains intact: no Java daemon adapter, credential, sync, transfer,
  dynamic menu, proxy route, or scheduler-blocking path may be restored.
- Kubernetes, remote-world, multi-region, Bedrock, browser/mobile, protocol,
  Discord, and live-player lanes retain their exact external-pending status.
- PostgreSQL remains the sole product truth. SQLite, event-all, and broker
  experiments cannot become a second store or effect authority.
- A selected input needs an owner contract, implementation task, deterministic
  proof, guarded proof where applicable, and a state row only after shipping.
- No fake command, sync, process manager, download, observer event, or success
  result may be used to fill a missing boundary.

## Compatible selections and reconsideration

`S-CONTRACT` is compatible only with `S-QUALITY` stale-output and mutation
proof, then with `S-SECURITY` identity declarations; it cannot imply Java or
Discord consumers. `S-SECURITY` is compatible with a daemon proposal only if
uncertainty denies and database work remains off the reactor. `S-CUTOVER` is
compatible with a future PostgreSQL-only data proposal, never SQLite or a
player transfer claim. `S-LOCAL-MENU` is compatible only with the retained
local resource surface. `S-QUALITY` can test any later proposal but does not
replace real adapters or live prerequisites.

Rejected executor/journal, runtime/lease, network/controller, high-cost store,
broker, public surface, and automation mechanisms are reconsiderable only when
the matching combination row closes its stated gap. Former inventory gaps have
an attempt but still need an owner-specific hypothesis and relevant bounded run;
external-pending IDs require their recorded prerequisite and rerun command. No
condition permits bypassing unavailable observer correlation or F-SAFETY
withdrawal.
