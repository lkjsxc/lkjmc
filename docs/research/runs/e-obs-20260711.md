## Correlation, faults, and secret handling

For all 60 lifecycle records, copied client and daemon IDs matched their
respective source records, but that only validates harness pairing. The client
request ID is client-generated, the daemon response ID is parsed from daemon
HTTP, and the observer event ID is an independently generated synthetic harness
field; it is never derived from the response ID. No independently emitted
observer event or provenance is available on this boundary. Therefore
`correlation-end-to-end` is `BLOCKED`/unsupported, not `PASS`; the self-test
fails mismatched and absent IDs, empty records, and blank client, daemon, or
observer IDs. `audit.tail` also exposes
action and target but no request ID.

| Fault attempt | Actual result | Status |
| --- | --- | --- |
| PostgreSQL `SELECT pg_sleep(1)` | query exit 0; following create took 11.366 ms | blocked for daemon-path delay |
| client times out during start | transport disconnect; later `instance.list` returned `ok` | observed continuation |
| child `exit 17` | `instance.start` returned `instance.error` | observed failure |
| missing bearer credential | HTTP 403 | observed denial |
| partial Velocity-shaped request then Velocity actor | closed request; complete request `auth.subject_denied` | blocked: Java adapter withdrawn |

The database query was an actual database delay but did not delay the daemon
handler; the product has no safe production fault hook. The withdrawn Java
adapter prevents calling the last item a plugin-disconnect proof. Thus the
named `fault-diagnosis` probe is mixed and remains blocked, despite the three
observed fault results above.

A generated canary was supplied only through a temporary forwarding-secret
file. A disposable known-positive artifact first proved the scanner detects the
canary and was removed. The final scan covered all 19 retained files, including
`.owned`, `index.json`, `index.sha256`, and `secret-canary-scan.json`; none
contained it. It retained no config tree or secret file. The scan reported
`positiveControlDetected=true` and `retainedFilesClean=true`.
