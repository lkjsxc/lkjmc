## Metrics, variance, and defects

The repaired baseline load p50 values were 0.623, 0.594, and 0.801 ms; p95
values were 0.998, 0.925, and 3.331 ms. Their medians were 0.623 and 0.998 ms.
These are debug-binary, local TCP doctor samples only: no PostgreSQL write, JVM
plugin, Minecraft, resource, or production capacity conclusion follows.

The load candidate previously failed 2/3 repetitions with `RuntimeError: load
worker did not stop`; those are rejected results, not retries. The repair added
EOF-aware request failures, a 0.5-second request timeout, bounded worker joins,
cancellation, process groups, and raw cleanup state. The new exact three-run
sequence passed without retrying a failed repetition; every raw summary records
zero live workers and process groups. The protocol lane is one expected blocker,
not a pass. The property compile failures remain harness authoring defects, not
product defects or test flakes.

Compose has no flake rate: its first `--mode all` command failed after the
migration matrix passed because the source migration omitted
`LKJMC_DATABASE_URL`; the corrected, second fresh `--mode restore` command
passed. This first-failure/second-success sequence is retained as a Compose
harness defect and correction, not erased as a green Compose run or counted as
a product flake.
