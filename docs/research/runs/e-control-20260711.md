## Post-launch fault and limits

For every journal execution, the harness routed a journal job through its async
candidate worker, durably claimed the effect, launched `sleep`, then terminated
and reaped it before a completion row. It observed one additional attempt and
no additional completion, removed that owned test row, and deliberately withheld
a retry. This controlled interruption proves neither parent-process crash
recovery nor that a real external effect was absent, so post-launch ambiguity
remains blocked.

`config.reload` applied pool and root changes while retaining its listener and
credential. The probe wrote `runtime.defaultJavaMemoryMb=0` and observed real
reload rejection; restart accepted the changed nonzero runtime value. Status
does not expose runtime memory, so this does not prove downstream runtime
application. Docker cleanup removed the lab database and containers. Minecraft,
Kubernetes, remote databases, and product adapter proof remain unattempted.
