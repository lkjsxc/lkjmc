# Contract research ideas

## Purpose

Imported contract/configuration candidates; none is shipped behavior.

## Catalog evidence

Source: supplied `experiments/catalog/contracts.md`. Each remains untested.

## Candidates

- `CT-DOMAIN-SHARDS` bounded command JSON domains; `CT-HAND-SCHEMA` hand schemas.
- `CT-RUST-SCHEMA` derive boundary schemas; `CT-DOMAIN-SOURCE` generate bindings.
- `CT-CHECKED-ADAPTER` compile/check mappings; `CT-ERROR-TAXONOMY` central errors.
- `CT-EFFECT-CLASS` declare effect class; `CT-IDENTITY-POLICY` declare subjects.
- `CT-CONFIG-DIR` compose config documents; `CT-NETWORK-DOC` validate network intent.
- `CT-LOCALE-SHARDS` compile domain catalogs; `CT-MENU-COMPILE` checked menu bundle.
- `CT-SOURCE-PATHS` validate docs paths/symbols; `CT-CATALOG-INDEX` bounded indexes.
- `CT-HANDLER-COVERAGE` prove command-handler mapping; `CT-MENU-SCHEMA` validate routes.
- `CT-WIDTH-CHECK` bounded pretty JSON; `CT-REMOVE-ALIASES` atomic removals.

## Decision boundary

Compare schema sources with shards and checked adapters, then combine the chosen
path with error, identity, effect, locale, and menu declarations. Measure drift
rejection, diff clarity, compile feedback, and generation cost before an owner
contract may change.
