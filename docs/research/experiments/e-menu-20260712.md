# E-MENU local and candidate menu evidence

## Purpose

Evaluate the retained local documentation menu, the repository-only menu catalog,
and daemon response-shape candidates without adding a Java daemon route, command,
or product claim.

## Baseline and method

The evaluation packet is the named route, failure, locale, malformed, outage, and
protocol-player probes. Its method reads the [GUI owner](../../product/gui/README.md),
[menu documents](../../contracts/menu-documents.md), and current
[catalog](../../../contracts/menus/README.json) before running only existing local
checks and isolated research code. Base commit: `4b9357a8e1a7949e0ebfe59c16af5196554f46cc`.

The retained catalog contains four local documentation metadata records. The
Paper menu consumes a generated documentation bundle directly, rather than that
catalog. The daemon response-shape test is a candidate-data experiment; its
responses have no Java consumer.

## Hypothesis and limits

A compiled, normalized documentation bundle can supply deterministic local
layout specimens and safe route/failure observations. Daemon-produced response
shapes can be inspected separately, but neither result establishes a player
inventory, action, grant, or daemon-backed Java menu.

F-SAFETY containment is an invariant. No Java daemon client, dynamic binding,
route registration, credential, mock player, protocol server, or placeholder
menu may be added. A static catalog, a layout specimen, or a daemon response is
not player proof.

## Workload and measurements

The runner builds the Paper jar, extracts its actual bundled JSON resource, and
records its diagnostic full count/digest plus a manifest-selected compiled count,
digest, normalized-path results, locale-check outcome, and layout specimens. The
explicit [source manifest](e-menu-20260712-source-manifest.json) retains the
normal bundle inputs but excludes this E-MENU run and decision record, so later
evidence prose cannot change the measured compiled selection. Specimens follow
current local source slots and are renderer-derived, not Bukkit/client goldens.

It runs the current static catalog and locale checks, the common document-core
tests, and the real PostgreSQL-backed daemon response-shape test. It also starts
a no-database daemon only to attempt a read command and records its error as an
outage boundary. Malformed bundle input is attempted through an isolated Java
candidate that calls the compiled `DocBundle` loader.

The runner sets the Minecraft guards for protocol/player attempts. Their required
nonzero `blocked:` outcomes are recorded as `BLOCKED`; they are never converted
to a pass. One fixed run uses seed `20260712`; elapsed time, exit code, hashes,
counts, and redacted output are retained under an owned `/tmp` root.

## Writes and reruns

Allowed committed writes are this research area, research indexes, coverage
records, the explicit source manifest, and an isolated candidate path only. No
owner, state, controller, plugin, adapter, route, or configuration file changes
are allowed.

After the runner is committed, invoke it from any directory:

```sh
ROOT="$(git -C "$REPO" rev-parse --show-toplevel)"
SCRIPT="$ROOT/docs/research/runs/e-menu-20260712.py"
(cd /tmp && python3 "$SCRIPT" capture)
(cd /tmp && python3 "$SCRIPT" replay --raw-dir <printed-owned-root>)
```

Replay verifies raw hashes, the manifest hash, every selected source hash, and
the manifest source-tip digest. It also verifies that the recorded repository
commit exists; it permits a later tip that changes only excluded evidence prose.
The run record must distinguish compiled-resource and daemon-model evidence from
an unavailable Java inventory or protocol player.
