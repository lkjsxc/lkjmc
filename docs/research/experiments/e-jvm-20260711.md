# E-JVM isolated adapter comparison

## Purpose

Compare JVM synchronization and execution candidates in a local, pure Java 21
harness without changing Java plugins, daemon behavior, controller state, or a
product claim.

## Constraints and baseline

Base commit: `d20e5e532db9d3a5577f567dd6a5a24fdc51eea1`. The current plugin
contracts withdraw every daemon-backed Paper/Folia and Velocity responsibility
pending trusted identity and session attestation. They retain local Paper menu
and docs presentation and Velocity MOTD/tab-list presentation only. This
experiment must not add a daemon client, credential reader, command, registry,
bridge, socket, HTTP client/server, mock daemon, or platform task registration.

The transport rows therefore model revision semantics only; they are not Java
networking evidence. The scheduler row uses a plain JDK executor, not a
Minecraft scheduler. Current constraints are
[plugin boundary](../../architecture/plugin/README.md),
[Paper/Folia withdrawal](../../architecture/plugin/paper-folia.md),
[Velocity withdrawal](../../architecture/plugin/velocity.md), and the
[synchronization boundary](../../product/sync/README.md).

## Hypothesis and candidates

A durable revision feed plus a bounded repair read can detect a dropped push and
converge without treating a notification as state. Adaptive polling, a bounded
long-poll wait, SSE event order, and push-plus-repair are compared against the
same in-memory revision history. Failed reconnects stop at a configured limit
and return an explicit offline result rather than a fabricated fresh state.

A future pipeline, fixed worker pool, virtual-thread worker, and typed
dispatcher are compared with actual JDK executors. The scheduler-facing action
must submit work and return before a blocked worker completes. The dispatcher
must reject a withdrawn effect type.

A static, pure Velocity topology lookup and correlated workflow outcomes test
that no dynamic discovery, transfer, or arrival is implied. Four authentication
and attestation combinations preserve one correlation ID and permit no external
effect; a fully eligible combination returns `RESEARCH_ONLY`, not success.

## Slice, faults, and measures

At immutable source tip `6fc8c2c059f07582f7b4dfb16508d0e562e6ce5e`, the
isolated Gradle project at `tests/research/e-jvm-20260711` used only JDK classes
and JUnit. It ran a fixed revision history with a missing event, two reconnect
failures, a blocked worker, eight blocking jobs, a withdrawn dispatch, absent
topology, and all four auth/attestation combinations. It recorded revision
continuity, repair reads, reconnect attempts, fixed versus virtual workers,
scheduler return-before-completion, dispatcher denial, static-route lookup, and
correlated outcome states.

That source-only Gradle project is intentionally absent from this evidence-only
tree. The imported hypothesis, run record, and decision retain its results; raw
command output and JSON remain under an owned `/tmp` directory. No production
module, plugin jar, product configuration, or controller file was written.

## External proof pending

A real Java transport, Minecraft scheduler, authenticated player session,
Velocity topology, and transfer outcome are not attempted: the shipped
withdrawal forbids the required Java adapter. Reconsidering them requires
trusted identity/session attestation, a separately approved disposable platform
harness, and new owner-contract work. The [run record](../runs/e-jvm-20260711.md)
retains the local rerun command and observed blocked lanes.
