# E-NETWORK declarative network comparison

## Purpose

Compare a bounded JSON network document and pure compiler with an isolated
imperative bootstrap model. This research does not select a controller, runtime,
command, schema, asset source, or product configuration.

## Baseline and hypothesis

At `4b9357a8e1a7949e0ebfe59c16af5196554f46cc`, bootstrap applies ordered
`BootstrapEffect` values through daemon adapters. The current Kubernetes planner
is pure, while cluster effects require guarded external access. Neither fact
selects this candidate.

The hypothesis is that one declared proxy, hub, disabled optional backend,
asset and plugin references, routing, and runtime policy can compile without
effects. Re-inspection can make a second local apply empty, while an imperative
model repeats starts. A failed added backend must stop its just-started child.

## Document and method

The candidate document is
[`e-network-document.json`](e-network-document.json). It uses only named
research digests; it requests neither a download nor executable Minecraft
asset. The compiler validates version, proxy and hub roles, enabled default
routing, asset/plugin references, and allowed runtime before producing local
resource specifications or Kubernetes ConfigMap, Deployment, and Service
objects.

The local adapter starts bounded, owned Python sleep children solely to observe
real process start, inspection, termination, reapply, removal, and rollback.
It is not a Minecraft runtime, fake process manager, or product adapter. The
Kubernetes adapter renders objects only. Its separate capability probe attempts
`kubectl version --client --output=yaml`; it may not apply an object without the
client, `LKJMC_KUBERNETES_SMOKE=1`, and a disposable namespace.

## Workload and probes

One fixed document has proxy and hub enabled and `events` disabled. The harness
runs these probes against fresh local roots: inspect/apply, reapply, enabling
events, rollback to the base document, removing events from the document,
controlled post-start failure, unsupported runtime policy, rendered manifests,
and a two-pass imperative comparison. Every process is terminated and recorded
before that root is released.

The imperative comparison is a deliberately small research model, not a claim
that the current bootstrap implementation starts duplicates. It runs each of
two desired resources twice to expose the distinction from inspect/reconcile.
The failure probe injects an error only after the `events` child really starts;
its rollback must observe that child terminated while the original proxy and
hub remain.

## Boundary and allowed writes

Candidate writes are limited to `docs/research/**` and owned `/tmp/lkjmc-e-network-*`
roots. It does not alter owner contracts, state matrices, controller state,
product source, process configuration, Kubernetes objects, assets, plugins, or
secrets. A future adoption needs a separate owner-contract, implementation, and
state task after a real adapter proof.
