# E-QUALITY quality-technique hypothesis

## Purpose

Define a bounded, non-product experiment that compares verification techniques on
representative pure, daemon, PostgreSQL, and checker boundaries.

## Catalog and baseline

Catalog evidence is `QV-PROPERTY`, `QV-STATE-MODEL`, `QV-FAULT-HOOK`,
`QV-FUZZ-JSON`, `QV-LOAD-HTTP`, `QV-PROTOCOL-BOT`, `QV-MUTATE-CHECKS`,
`QV-MIGRATION-MATRIX`, `QV-RESTORE-PROOF`, `QV-CLOCK`, `QV-RANDOM-SEED`,
`QV-SECRET-CANARY`, and `QV-PERF-BUDGET` in
[verification ideas](../ideas/verification.md). Base commit is
`d20e5e532db9d3a5577f567dd6a5a24fdc51eea1`. The baseline is targeted unit,
fault-harness, truth-probe, lab, and Compose checks; it has no committed
cross-technique comparison.

## Hypothesis and slice

A deterministic property/fuzz suite, a test-only state/fault model, real local
TCP load interrupted by a daemon kill, and disposable Compose migration/restore
runs expose distinct boundaries without adding a product path. Existing checker
mutation, seed replay, and artifact-redaction probes are comparison controls.

## Invariants

- The controller state and shared product configuration are not written.
- Fault markers remain test-only and release inspection remains required.
- Load uses an ephemeral daemon, ports, roots, and generated token only; bounded
  request and worker-stop deadlines plus process-group cleanup must leave no
  worker or daemon process alive.
- Compose uses a unique project and disposable volume; restored data is local.
- Protocol proof is attempted through its guard and remains blocked if the
  withdrawn Java adapter has no local-safe client path.
- Artifacts are bounded, redacted, and ignored; no generated secret is printed.

## Workload and comparisons

Run each deterministic local technique three times without retrying failures.
The parser corpus is 2,048 deterministic byte sequences and generated policy
cases use 256 fixed seeds. The state model traverses duplicate, restart, and
pre-effect-fault states over 64 fixed seeds. The load comparison uses 8 workers
and 25 doctor requests each: one no-fault baseline and one mid-flight process
kill followed by a fresh-process recovery check. Record wall time, successful
request latency, expected transport failures, recovery, worker/process cleanup,
flake count, and maintenance cost. A bounded timeout is a harness safety limit,
never a product capacity or latency claim.

Run real PostgreSQL migration checks and a full-database custom-format dump,
restore, and daemon boot in a disposable Compose project when Docker is
available. The restore does not prove production recovery. Run the guarded
protocol command even when its expected result is blocked.

## Allowed writes

At immutable source tip `62cd2945b92d7a0af1e47962989d204903720eb9`, candidate
writes were limited to `crates/**`, `tests/**`, `scripts/**`, and
`docs/research/**`. This consolidation deliberately retains only the research
documents; the candidate paths are not current-tree rerun targets. A hypothesis
commit preceded experiment code. The result is a run and a separate decision;
it cannot update state or select adoption.

## Source-tip rerun entry points

The source-tip commands were `cargo test -p lkjmc-core quality_`,
`cargo test -p lkjmc-daemon state_model_`,
`python3 tests/quality/quality_load_fault.py`, and
`python3 tests/quality/quality_compose.py`. Guarded protocol and existing
controls are recorded with their exact commands in the run document.
