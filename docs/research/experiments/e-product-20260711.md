# E-PRODUCT bounded journey hypothesis

## Purpose

Compare the current documented operator and local-document player entrypoints
with a research-only curated-help model, without adding an adapter, command,
route, controller action, or product claim.

## Catalog and baseline

This evaluates `PX-OPERATOR-JOURNEY`, `PX-PLAYER-ONBOARD`, `PX-TASK-MENU`,
`PX-WAKE-PROGRESS`, `PX-TRANSFER-RECOVERY`, `PX-CLAIM-VISUAL`,
`PX-PROGRESSION`, `PX-ADVENTURE-CATALOG`, `PX-SOCIAL-ENTRY`,
`PX-ADMIN-CONSOLE`, `PX-CHAT-FALLBACK`, `PX-PLAYER-DOCS`, `PX-BEDROCK-UX`,
`PX-ACCESSIBILITY`, `PX-LOCALE-TONE`, `PX-FEATURE-PRUNE`, and
`PX-DEGRADED-NETWORK` from [product ideas](../ideas/product.md). The product
base is `af40e5569d4bc48c71eba1d2524d0b4f4a0f11e4`.

The baseline is the actual CLI help, guarded local web smoke, packaged broad
local documentation bundle, locale catalog, and contained Java source. The
candidate is a six-document curated-help selection model. It is an evaluation
input only: current `/docs` remains the broad bundled browser, and no curated
route, task menu, or chat command is registered.

## Hypothesis and invariants

A fixed, player-safe document selection can expose the current boundary more
clearly than a broad bundle, but it cannot establish first-join completion,
chat fallback, menu interaction, transfer, claim protection, or gameplay.

- Write only `docs/research/**` and ignored `/tmp/lkjmc-e-product-*` artifacts.
- Do not alter owner docs, product source, adapters, controller records, or state.
- Do not present a static, CLI, database, or web result as Minecraft proof.
- Preserve F-SAFETY containment: Java daemon adapters and dynamic player paths
  remain absent; a guarded Java diagnostic must be `BLOCKED`, never pass.
- Retain only redacted, bounded output; no generated secret is printed or committed.

## Slices and workload

The research runner builds the real documentation bundle, executes CLI help,
locale and containment checks, and invokes the guarded local web smoke. It
records the current bundle size and whether the curated selection and operator
quickstart material coexist in that bundle. This is genuine documentation, CLI,
and local web evidence, not a user-comprehension measurement.

The runner also executes the real core adventure and daemon purchase-preflight
unit tests. Compose verification supplies the PostgreSQL-backed wake queue,
temporary-session, ledger, exchange, and replay checks. These are durable-model
evidence only. The runner sets each withdrawn Java smoke guard to `1`; its
required nonzero, `blocked:` result is retained as the exact unavailable-menu,
protocol, adventure, and playable attempt.

Use seed `20260711`, one deterministic run, and no synthetic Minecraft client
or player account. Run the baseline again through the same runner after the
candidate selection model so environment drift is visible. Candidate comparison
is document membership and boundary wording, not latency or task completion.

## Measurements and dispositions

Record command, exit, elapsed time, sanitized output hash, bundle document count,
curated-selection membership, locale parity outcome, and every guarded outcome.
The comparison must separately label local-model success, database-model success,
and external/player proof. A missing real player surface is `BLOCKED`.

Feature disposition compares journey value against implementation, attestation,
maintenance, and proof cost. The expected result is non-adoption for unavailable
player surfaces, while preserving durable-model observations for later work.
