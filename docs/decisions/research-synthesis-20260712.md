# Research synthesis decision 2026-07-12

## Purpose

Record the active target constraint derived from E-SYNTHESIS without promoting
experiment code or a research result to product behavior.

## Decision

No experiment mechanism is adopted. The only selected items are non-product
proposal inputs: strict contract generation, fail-closed credential repair,
deterministic falsification, PostgreSQL cutover rehearsal, and the existing
local menu boundary. They need separately approved owner contracts and fresh
implementation evidence before they can change a product decision.

## Rationale

The experiments establish useful bounded observations but do not close the
required combinations. A journal cannot determine whether a post-launch effect
occurred, an observer event has no independent daemon provenance, and Java
identity/session attestation is absent. Remote, Kubernetes, and player-client
lanes either did not run or recorded their exact missing prerequisite.

## Consequences

- Retain PostgreSQL truth, pure-core/effect separation, redacted diagnostics,
  guarded external proof, and local-safe Java containment.
- Do not select an executor, actor, journal, lease, broker, controller, Java
  daemon adapter, transfer, dynamic menu, public surface, high-cost store, or
  automated remediation path.
- Reconsider a rejected mechanism only when the matching condition and
  compatible combination in the [E-SYNTHESIS decision](../research/decisions/e-synthesis-20260712.md)
  is proved by a separate owner task.
- The [execution handoff](../execution/tasks/e-synthesis-20260712.md) maps the
  inputs and hard gates to future A-* work without claiming controller state.

## Boundary

This target decision changes neither the current capability matrices nor the
controller ledger. State remains the only shipped-behavior record.
